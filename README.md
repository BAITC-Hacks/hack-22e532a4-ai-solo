# BaqBaq

**ИИ-агент сверки организационных изменений с проверяемыми источниками** для HackAlem AI, спец-трек Казахтелеком «Анализ организационной структуры и функционала».

BaqBaq принимает несколько документов в комплектах «до» и «после», извлекает структуру и функции, ищет смысловое покрытие, отмечает потенциальные потери, пересечения и конфликты интересов, а затем формирует заключение. Каждый существенный вывод открывает точный фрагмент конкретной версии документа.

> Это хакатонный аналитический прототип, а не юридическое заключение. Выводы требуют проверки ответственным сотрудником.

## Что реализовано

| Must-have трека | Артефакт |
|---|---|
| Сохранённые и добавленные подразделения | Реестр структуры и findings `structure_*` |
| Сопоставление функций и возможные потери | Гибридное смысловое сопоставление, coverage check, связи переноса/изменения |
| Дублирование и конфликт интересов | Раздельные проверки объекта, области и полномочий |
| Источник каждого вывода | Immutable `DocumentVersion` + `SourceSpan`, точная цитата и локатор |
| Понятное заключение | Рабочий экран, Markdown/HTML-экспорт, ограничения и рекомендации |

Дополнительно: история решений сотрудника, журнал реальных инструментов и времени, уточняющий агент, idempotency key, изоляция сравнений, dark theme, responsive UI и подготовленная контрольная пара.

## Быстрый запуск на Windows

```powershell
git clone https://github.com/BAITC-Hacks/hack-22e532a4-ai-solo.git
cd hack-22e532a4-ai-solo
.\run.ps1
```

Скрипт создаст `.venv`, установит зафиксированные зависимости и откроет сервер на [http://127.0.0.1:8000](http://127.0.0.1:8000). Если браузер не открылся автоматически, перейдите по адресу вручную.

Ручной запуск:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## Проверка

```powershell
.\verify.ps1
```

Команда использует отдельные временные БД в unit-тестах, не удаляет пользовательские загрузки и возвращает ненулевой код при провале. Фактический последний результат: **17/17 tests** и **24/24 evaluation cases**. Подробности: [results/evaluation.md](results/evaluation.md) и [results/BUILD_READINESS.md](results/BUILD_READINESS.md).

## Контрольный сценарий

1. Нажмите **«Загрузить контрольную пару»** — локальные редакции 8 и 9 проходят тот же parser pipeline, что пользовательские файлы.
2. Нажмите **«Запустить анализ»**.
3. В таблице найдите перенос `5.4.4 → 5.3.3`, откройте обе цитаты и журнал.
4. Найдите изменения `9.37` и `12.1.4`; интерфейс показывает изменение формулировки, а не недоказанную потерю.
5. Зафиксируйте решение сотрудника и экспортируйте Markdown или HTML.

Пути demo-файлов настраиваются в `.env`; оригиналы не коммитятся.

## Модельный режим

По умолчанию включён честно обозначенный `offline`-режим: детерминированное извлечение, локальный subword/lexical semantic index и evidence resolver. Он полностью демонстрирует основной продуктовый путь без ключа, но **не выдаётся за работу LLM**.

Для live-режима:

```powershell
Copy-Item .env.example .env
# В .env задайте BAQBAQ_MODEL_MODE=live, OPENAI_API_KEY и при необходимости OPENAI_BASE_URL
```

Используется OpenAI Responses API через backend. Модель получает только разрешённые фрагменты, возвращает `source_ids`, а цитаты и локаторы подставляет сервер из exact store. Ключ никогда не отправляется во frontend и не пишется в журнал.

## Поддержанные форматы

- **DOCX** — OOXML в порядке абзацев и таблиц, автоматическая нумерация, пункт/абзац как локатор.
- **PDF** — только текстовый слой, страница и фрагмент. Скан без OCR получает статус `needs_attention` и не даёт «нулевой риск».
- **XLSX** — лист и диапазон ячеек; формулы читаются как сохранённые значения, макросы не исполняются.

Legacy DOC/XLS и OCR не заявлены как поддержанные.

## Архитектура

```text
Upload/API → Ingestion → SQLite exact store → Function registry
                                      ↓
                         local semantic candidates
                                      ↓
                       coverage / overlap / authority
                                      ↓
                 evidence resolver → findings → report/UI
                                      ↘ model adapter / agent
```

- **Exact layer:** хеши, версии, стороны, оригинальные цитаты, локаторы и решения сотрудника.
- **Semantic layer:** действие, объект, владелец, область, полномочие и кандидаты соответствия.
- **Gateway/API:** единая граница для UI, evaluator, агента и отчёта.

Подробнее: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## API

После запуска: [Swagger UI](http://127.0.0.1:8000/docs).

Основные маршруты: создание сравнения, multipart-загрузка по сторонам, запуск анализа, results/source viewer, вопросы агенту, решения сотрудника и экспорт отчёта.

## Ограничения

Полнота вывода ограничена загруженными документами; нейронная embedding-модель не включена в offline-пакет; OCR, DOC/XLS и DOCX/PDF-экспорт не реализованы; live LLM без credentials не проверялся. Полный список — [docs/LIMITATIONS.md](docs/LIMITATIONS.md).
