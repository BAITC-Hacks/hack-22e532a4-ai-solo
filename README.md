# BaqBaq — куда ушла функция при реорганизации?

ИИ-агент сверки организационных изменений с проверяемыми источниками. HackAlem AI, спец-трек Казахтелеком «Анализ организационной структуры и функционала».

Сотрудник загружает комплекты «до» и «после», проверяет таблицу изменений и точные фрагменты, сохраняет своё решение и экспортирует заключение. Выводы рекомендательные; отсутствие совпадения не доказывает утрату функции в компании.

[Проверка за 3 минуты](#проверка-для-жюри) · [Быстрый запуск](#запуск) · [Архитектура](docs/ARCHITECTURE.md) · [Результаты проверок](results/BUILD_READINESS.md) · [Ограничения](docs/LIMITATIONS.md)

**Статус:** MVP. Offline + локальные embeddings проверены; реальный Live API прошёл серверный smoke-тест на синтетической паре (анализ, вопрос, HTML). Приложение развёрнуто на сервере только на loopback; публичный домен/HTTPS ожидают исправления DNS. Видео и презентация пока не опубликованы. [Состояние развёртывания](deploy/README.md).

## Проблема → решение

При изменении положений функция может сменить пункт, подразделение или формулировку. Обычного текстового сравнения недостаточно, чтобы установить её судьбу.

BaqBaq предлагает соответствия между функциями и владельцами, показывает индикаторы рисков и связывает выводы с точными фрагментами. Сотрудник проверяет интерпретацию и сохраняет решение отдельно от результата алгоритма.

## Проверка для жюри

После запуска приложения нажмите **«Проверить на демо»**. Создаётся отдельное сравнение; текущие загрузки не удаляются. Контрольная пара проходит обычный pipeline, готовые выводы не подставляются.

1. **Изменение:** откройте карточку «Куда ушла функция?», «Что изменилось?» или «Что требует проверки?». Карточки выбираются из фактических результатов; отсутствующие категории явно обозначаются.
2. **Доказательство:** прочитайте цитаты, редакции и границу вывода. Сходство — не доказательство правомерности реорганизации.
3. **Решение:** добавьте комментарий, сохраните решение и откройте HTML-отчёт выбранного запуска.

Три минуты — целевой маршрут после подготовки окружения, не гарантированная скорость. Первая загрузка весов требует интернета и дополнительного времени. Без локальных оригиналов используется явно обозначенный синтетический комплект. [Подробный сценарий](docs/DEMO_SCRIPT.md).

## Три ключевые возможности

| Вопрос проверяющего | Что показывает BaqBaq |
|---|---|
| Куда ушла функция? | Кандидаты переноса, разделения и объединения с владельцами до/после |
| На чём основан вывод? | Точный текст, редакцию, локатор и ограничения интерпретации |
| Кто принял решение? | Историю решений сотрудника и комментарии; аутентификация личности пока не реализована |

Отличие нашего подхода — цепочка **функция → соответствие → источник → решение**, а не только ответ чата. Это позиционирование, не заявление об уникальности на рынке.

## Стек и границы масштабирования

| Слой | Реализация |
|---|---|
| Интерфейс | Адаптивные HTML/CSS/JavaScript, светлая и тёмная темы |
| API и точные данные | FastAPI, SQLite, локальные файлы |
| Семантический поиск | FastEmbed / multilingual MiniLM, CPU |
| Агент | OpenAI Responses API, ограниченные инструменты и проверка источников |
| Проверка | pytest, документные сценарии, регрессия реальной пары |

Текущая версия предназначена для локальной проверки, не для многопользовательского enterprise-развёртывания. Очередь задач, восстановление после сбоя, роли, изоляция организаций и нагрузочные измерения — следующие этапы. Смена SQLite сама по себе не решает эти задачи.

## Воспроизводимость без преувеличений

Хеши файлов и точные цитаты отделены от семантических интерпретаций. Снимок запуска закрепляет документы и машинные результаты; решения сотрудника имеют собственную историю. Кеш модели не гарантирует одинаковый ответ при новом запросе. Версия весов не закреплена отдельным commit-хешем. Экспорт может измениться после нового решения сотрудника.

## Запуск

Windows, Python 3.12:

```powershell
git clone https://github.com/BAITC-Hacks/hack-22e532a4-ai-solo.git
cd hack-22e532a4-ai-solo
.\run.ps1
```

Откройте http://127.0.0.1:8000. При первом анализе FastEmbed загружает multilingual MiniLM; дальнейшие вычисления embeddings локальны на CPU. Интернет нужен для установки пакетов и первой загрузки весов.

Для установки без загрузки весов задайте `BAQBAQ_SEARCH_MODE=lexical`: это явно обозначенный лексический режим, не embedding-поиск. Полный снимок зависимостей проверенного Windows/Python 3.12 окружения — `requirements-windows.lock.txt`; основной список — `requirements.txt`.

Кнопка контрольной пары использует локально подключённые оригиналы. Если они отсутствуют, она загружает явно обозначенные `SYNTHETIC_*.docx`. Их исходные данные находятся в `app/fixtures.py`; анализ выполняется обычным алгоритмом. Оригиналы организатора в Git не включены.

## Что реализовано

| Требование | Реализация и границы |
|---|---|
| Структура | Сохранённые, добавленные и отсутствующие подразделения; явно указанное преобразование 1:1. Юридический статус не утверждается |
| Сопоставление функций | Извлечение без известных номеров разделов, кандидаты переноса, разделения и объединения; список проверенных кандидатов в снимке запуска |
| Потери / дублирование / конфликт | Осторожные индикаторы; учитываются область и тип полномочий. Непрочитанный комплект получает partial |
| Источники | Хеши файлов, редакции, точные фрагменты; сервер проверяет comparison_id и снимок запуска |
| Заключение | HTML/Markdown, ограничения, источники, решение и комментарий сотрудника; экспорт по конкретному run_id |

Интерфейс поддерживает загрузку нескольких файлов, поиск и фильтры, точные цитаты, историю запусков и решений, журнал backend, уточняющий вопрос и новое сравнение.

## AI и два слоя

- **Exact:** SQLite, неизменяемые версии документов и SourceSpan, снимок состава каждого AnalysisRun, решения сотрудника.
- **Semantic:** FastEmbed `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, 384 измерения, CPU. Производный кеш в SQLite; точные цитаты не восстанавливаются из векторов.
- **Offline:** детерминированное извлечение и сопоставление; может использовать настоящие локальные embeddings, но не выдаётся за LLM.
- **Live:** OpenAI Responses API для атомарного извлечения, сопоставления и вопросов через инструменты. Ответы/ссылки валидируются, результаты извлечения и сопоставления кешируются по входу, модели и версии инструкции.

Для live:

```powershell
Copy-Item .env.example .env
# Локально задайте OPENAI_API_KEY, BAQBAQ_MODEL_MODE=live,
# OPENAI_MODEL и при необходимости OPENAI_BASE_URL.
.\run.ps1
```

После переключения режима создайте **новое сравнение**: режим существующих сравнений сохраняется.

Агент может вызвать поиск источников, точное чтение, поиск функций, сравнение источников, проверку покрытия и получение результатов. Не более 6 шагов и 6 инструментов за шаг; API timeout 45 секунд и один повтор. Неизвестный источник или невалидный JSON — ошибка, без автоматического присвоения цитаты. Дословные цитаты ответа собирает сервер.

**Live verification: smoke PASS** — 23 сентября 2026 на сервере проверены реальная модель `gpt-4.1-mini`, синтетическая пара, вопрос агенту и HTML-отчёт. Первый прогон выявил неполную запись модели; добавлена строгая JSON-схема, повторный прогон успешен. Это не экспертная оценка качества на исходных документах.

## Проверка

```powershell
.\verify.ps1
```

Проверка использует временные БД и не затрагивает рабочие загрузки:

- 53 теста: документы, изоляция, история, неполное извлечение, модельные ошибки, цикл инструментов и ограничения;
- прежние 24 probe-проверки строк — только вспомогательная регрессия;
- **24 документных сценария**: загрузка → анализ → источники → изоляция → экспорт, в том числе review и история.

Встроенные сценарии синтетические и заранее размеченные. Они не являются независимой оценкой точности. Основной отчёт: [results/document_evaluation.md](results/document_evaluation.md), машинный результат: [results/document_evaluation.json](results/document_evaluation.json). Для них нельзя выдавать precision/recall вспомогательного класса related за качество выявления рисков.

Отдельная проверка embeddings:

```powershell
$env:BAQBAQ_SEARCH_MODE='fastembed'
.\.venv\Scripts\python.exe scripts\evaluate_documents.py
```

[Результат FastEmbed](results/document_evaluation_fastembed.md): 24/24. Опциональная регрессия исходных редакций: `python scripts/verify_real_pair.py`; требует подключения локальных оригиналов. Найдены 2 сохранённых / 2 добавленных подразделения и три опорные связи. Это не полная экспертная разметка исходных документов.

## Форматы и данные

DOCX: OOXML, порядок абзацев и таблиц, явная/автоматическая нумерация. PDF: текстовый слой и локатор страницы. XLSX: строки таблицы, явный владелец и функция, лист/ячейки. Пустые сканы требуют OCR; смешанный неполный комплект не получает обычный completed.

Подключение оригиналов: `BAQBAQ_DEMO_BEFORE`, `BAQBAQ_DEMO_AFTER` в локальном .env. Не публикуйте ключи и организаторские документы. Live-модель получает текст разрешённых фрагментов; проект не заявляет, что данные никогда не передаются внешнему провайдеру.

## API и архитектура

Swagger: http://127.0.0.1:8000/docs. Основные API: comparisons, documents, analyze, result?run_id, runs, progress, sources, review, ask, report?run_id.

`app/registry.py` — извлечение; `search.py` — embeddings; `analysis.py` — сопоставление/риски; `gateway.py` и `agent.py` — инструменты и агент; `db.py` — exact layer; `reporting.py` — заключение.

## Ограничения

Юридическая верификация реорганизации, сложные организационные слияния, OCR, старые DOC/XLS, DOCX/PDF-экспорт, MCP, внешние нормативы и аварийное восстановление незавершённого запуска не реализованы. Offline-разделение и объединение — кандидаты по текстовым компонентам. Анализ независимости ограничен явно извлечённым владельцем и полномочиями, без графа подчинённости. Семантическая истинность каждого вывода не гарантируется существованием ссылки: изменённые соответствия требуют проверки сотрудником.
