# Реализация после аудита · 23.09.2026

## Обновление 0.3.0 по решению владельца

Публичное демо и обязательный вход заменены открытым Live. Документы и результаты разделены по случайной HttpOnly cookie; старые приватные записи не открываются. Первый экран — только рабочие проверки и загрузка двух редакций. Предоставленный прозрачный логотип используется без дублирования названия; единый sans-serif, компактная сетка и нейтральная палитра. Длинный Live-прогон остановлен; перед сдачей выполняется только короткая сквозная проверка.

## Выполнено ранее в релизе 0.2.0 (история, доступ изменён выше)

- Публичная главная отделена от защищённого workspace/Live; оба режима запуска используют один репозиторий.
- Главный экран сокращён до задачи и одного демонстрационного маршрута; предоставленные логотипы BaqBaq и Казахтелекома подключены как локальные assets.
- Демонстрационный набор одинаков на всех машинах; содержит преобразование, перенос, отсутствие соответствия и дублирование. Публичный снимок честно помечен Offline/lexical.
- Отрицание, модальность и периодичность больше не теряются только из-за сходства текста. Заголовки подразделений не считаются функциями. Владельцы с «внутреннего контроля» не обрезаются на слове «контроля».
- Номинативные подпункты наследуют действие из вводного пункта; этот контекст включён в источники интерфейса и отчёта.
- DOCX учитывает start/startOverride и наследуемую нумерацию стилей. Неподдержанные варианты требуют предупреждения, полной универсальности не заявлено.
- Повреждённый OOXML даёт 422 и запись неполного комплекта; ограничены распаковка ZIP, страницы PDF, размеры XLSX. Формулы не выдаются за рассчитанные значения.
- Снимок включает функции, входной хеш различает стороны, исторический поиск сначала ограничивает документы. Анализ возвращает собственный run_id.
- Атомарная блокировка второго анализа того же сравнения. После перезапуска единственного worker незавершённые запуски помечаются failed, не висят как running.
- Обновлены FastAPI/Starlette; добавлены серверные сессии, ограничитель входа и cross-site записей, сохраняемые лимиты вызовов OpenAI и usage.
- История сравнений, режим нового расчёта, подсветка различающихся слов, видимые предупреждения парсера; машинное основание отделено от решения сотрудника.
- Отчёт начинает с рисков и действий, содержит паспорт и контекст. GitHub README и CI описывают реальный способ проверки.

## Не закрыто и не скрывается

1. Независимая экспертная разметка полного реального комплекта, измерение precision/recall по видам ошибок. Разработческие тесты не заменяют её.
2. Многопользовательские роли и изоляция организаций, фоновые очереди, нагрузочный тест, квоты диска и проверка восстановления backup — этап пилота, не готовые свойства MVP.
3. Пиннинг весов по immutable revision и долларовый учёт расходов. Сейчас фиксируются версия модели/пакетов, хеш кода, request caps и токены, но не гарантируется идентичность нового Live-ответа.
4. Сложные слияния организационных структур, граф независимости/подчинённости, OCR, MCP и выгрузка DOCX/PDF.
5. Видео и оформленная презентация. Подготовлены сценарий и питч; отправка решения на платформе выполняется владельцем.
