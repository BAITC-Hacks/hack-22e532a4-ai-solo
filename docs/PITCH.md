# BaqBaq — короткий питч, 3 минуты

Это текст выступления, не готовое видео и не опубликованная презентация.

## 0:00–0:25 · Боль

При реорганизации документы меняются быстрее, чем человек может сверить все обязанности. Удалённая строка может означать и потерю функции, и обычный перенос в другое подразделение. Ошибка здесь превращается в пробел ответственности.

## 0:25–1:00 · Подход

BaqBaq сравнивает комплекты «до» и «после» по функциям и владельцам. Для каждого вывода показывает исходные цитаты, пункты, редакции и границу интерпретации. Точный источник хранится отдельно от ответа модели. Алгоритм предлагает; сотрудник принимает решение.

## 1:00–2:00 · Живой показ

Открыть baqbaq.world → загрузить обе редакции → запустить Live → открыть найденное изменение и обе цитаты. Если есть потенциальная потеря, подчеркнуть: соответствие не найдено только в загруженном комплекте. Сохранить решение и открыть заключение. Не обещать заранее конкретные категории или время расчёта.

Если API недоступен: показать ранее скачанный HTML с паспортом запуска и честно обозначить, что это прошлый результат. Публичный интерфейс работает только в Live, без входа и без демонстрационных заглушек.

## 2:00–2:35 · Проверяемость

Показать паспорт запуска и GitHub. Доступны тесты полного пути загрузка → анализ → источники → отчёт, негативные сценарии и регрессия трёх известных связей реальных редакций. Это не промышленная метрика точности; независимая экспертная разметка — следующий этап.

## 2:35–3:00 · Ценность и пилот

Первый пилот: несколько комплектов реорганизации и эксперт Казахтелекома. Измеряем время поиска основания, число исправленных гипотез и precision/recall отдельно для потерь и дублей. Цель — сократить труд сверки и сделать решения проверяемыми. Не объявлять проценты экономии до измерения.
